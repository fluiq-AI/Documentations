The victim did nothing.

That's the detail worth sitting with. No link clicked, no attachment opened, no credential typed into a convincing login page. An email arrived. The assistant read it, because reading email is the assistant's job. Internal data left the building.

The vulnerability is EchoLeak, CVE-2025-32711, CVSS 9.3, disclosed by Aim Security in June 2025. It's worth a proper teardown, because more than a year later it's still the cleanest illustration of why AI security is an architecture problem rather than a filtering problem.

It was the first AI vulnerability to receive a no-action CVE from Microsoft — meaning customers had nothing to patch, because there was nothing on their side to patch. And it is, as far as public record goes, the first documented zero-click indirect prompt injection against a production AI system.

Itay Ravia, who heads Aim Labs, put it plainly:

EchoLeak is a reminder that even robust, enterprise-grade AI tools can be leveraged for sophisticated and automated data theft.

The chain, one step at a time

What makes this instructive isn't any single trick. Every individual layer Microsoft had built was reasonable. The attack worked because it walked through them in order.

Step 1 — Delivery. An email arrives in the target's inbox. Nothing about receiving email is a privileged action. There is no decision point here, for the user or for anyone else.

Step 2 — Ingestion. Copilot's whole value proposition is having context. So it reads mail. The attacker's content is now inside the model's context window, sitting beside the victim's actual corporate data — with no boundary marking one as instructions and the other as data. This is the definition of indirect prompt injection: the attacker never speaks to the model, the attacker plants text where the model will go looking.

Step 3 — Classifier bypass. Microsoft ran an XPIA (cross-prompt injection attack) classifier precisely to catch this. The crafted content got past it. Note what this establishes: a dedicated, funded, production injection classifier at a company with world-class security engineering was not sufficient. That's not an indictment of the classifier. It's evidence about the category.

Step 4 — Redaction bypass. Copilot redacted markdown links to stop exfiltration through URLs. The attack used reference-style markdown, which the redaction logic handled differently. A parsing gap, not a policy gap — which is the most common kind.

Step 5 — Exfiltration. Auto-fetched images did the actual work. The client fetches an image URL without asking anyone. Embed the stolen data in that URL and the exfiltration is performed by the trusted client, on the trusted network, as a completely ordinary image request. Combined with a Teams proxy to get around remaining restrictions, the data was out.

Five steps. Zero clicks.

Why zero-click is a category change

Most security models have a human somewhere in them. Someone has to click, install, approve, or be fooled. That human is slow and imperfect but they are a real control, and a great deal of security tooling is ultimately about making their decision easier.

EchoLeak removes them.

The agent is the one that reads untrusted content, and it reads it because that's what you deployed it to do. There is no moment where a person could have been more careful. Awareness training has nothing to attach to.

Which means the control has to be architectural — in what the agent is able to do once it has been fooled. Not in whether it can be fooled.

Nothing malfunctioned there. An agent with real database credentials read attacker-controlled text and acted on it, which is exactly what an agent with real database credentials does. The vulnerability was the permission grant.

The first confirmed malicious MCP package in the wild showed up in September 2025. OWASP published a dedicated Agentic Security Initiative (ASI) Top 10 in December 2025 to cover the model-as-actor layer, which the classic application-security lists were never shaped for.

Tool poisoning: a supply chain attack on the context window

Worth pulling out separately, because it's the most under-appreciated item on the list.

MCP tool poisoning — malicious instructions embedded in tool descriptions and metadata rather than in tool outputs — was first described by Invariant Labs in April 2025, with Simon Willison writing the canonical practitioner explainer the same month. Related variants: "rug pull" attacks, where a tool silently redefines itself after you've installed and approved it, and cross-server shadowing, where one server's tool description manipulates the model's use of another's.

Truefoundry's framing is the one I'd keep: this is a supply-chain attack on the agent's context window. That places it closer to dependency poisoning than to prompt injection in the classic sense. The text you never wrote, never reviewed, and pulled in from a registry is being read by your model as authoritative instruction.

You already have opinions about unreviewed dependencies. Tool descriptions are a dependency.

Injection isn't a text problem anymore

If your mental model of prompt injection is "weird strings in the user message," it's a version behind.

Nagaraja et al. (IEEE FLLM, November 2025) reported up to 64% attack success embedding stealth instructions inside ordinary-looking images against GPT-4-turbo. CrossInject (ACM MM 2025) reported a 30.1 percentage-point improvement in attack success over prior perturbation-based methods. A Cloud Security Alliance research note in March 2026 catalogued the families — typographic, steganographic, perturbation-based — plus physical-world variants documented in January 2026, and landed on the sentence that explains why this works at all:

Vision-language models do not distinguish between the visual content a user intends to show the model and instructions embedded in that content.

Which is the same failure as EchoLeak, in a different modality. There is no channel that carries "this part is data" alongside the pixels.

So build for the assumption that it lands

Here is the reframe I'd argue for, and it's the one that follows directly from the EchoLeak chain: stop trying to build a model that can't be fooled, and build the system around it so that when the model is fooled — and it will be — nothing important breaks.

That is not a guardrail thesis. It's a blast-radius thesis. Three surfaces do the work:

Tool allowlists. An agent that can call any tool has capability with no constraint. Scope tools per agent, tightly, and treat the scope as a security boundary rather than a convenience default. Re-read the Supabase incident with this in mind: the exploit was a permission grant that nobody had scoped.

Output gates. OWASP's own LLM Prompt Injection Prevention Cheat Sheet recommends scoring the primary model's response against a policy before it's returned to the user or passed to a downstream tool. Snyk makes the same argument from the product side — that the two-sided hook, input and output, is what makes a guardrails architecture robust rather than decorative. Input-only filtering assumes you catch the attack going in. Output gating assumes you didn't.

Per-hop scanning. In a multi-agent chain the dangerous output is frequently the intermediate one — the summary Agent A hands to Agent B, carrying an instruction it picked up from a document. If you only scan the final response to the user, that hop is unobserved by construction.

Applied against the kill chain above:

Chain stepWhat contains it
Untrusted content enters contextNothing. Accept this. It's the job.
Injection classifier is bypassedNothing reliably. Assume bypass.
Model acts on the instructionTool allowlist — is this agent even permitted to do that?
Data is shaped for exfiltrationOutput gate — scan the response before it leaves
Data crosses an agent boundaryPer-hop scanning — the intermediate is the payload

The first two rows are the point. Two of five steps have no good control, and a design that depends on those two is a design that fails whole.

Why a gateway can't do the third row

A proxy sitting in front of your LLM provider sees requests and responses crossing that boundary. It does not see Agent A handing its summary to Agent B inside your process, because that exchange never touches the provider API.

This isn't a feature gap that a proxy vendor can close in a sprint. It's a consequence of where the software sits. In-path tools see the API boundary; in-process instrumentation sees the hop.

import fluiq

fluiq.instrument(api_key="flq_...")
fluiq.secure(mode="block", guardrail="strict")

Fluiq instruments in-process, so every hop in the agent DAG is a scannable event with parent resolution handled automatically. Input scanning covers injection, jailbreak, skeleton-key and semantic attacks; output scanning runs at every hop rather than only at the user boundary; tool allowlists and exfiltration checks live in a named guardrail policy you configure once and reference by slug.

Image media in the trace is OCR'd and the extracted text goes through the same scanners as prompt text.

The honest part

OWASP's own position is that prompt injection cannot be fully eliminated. Any vendor telling you otherwise is selling you something, and I'd rather be the vendor that says so.

Two limits worth stating plainly about what we ship:

OCR catches typographic attacks — text rendered into an image. It does not catch steganographic or perturbation-based ones. Those remain open research. If your threat model includes an adversary embedding instructions below the perceptual threshold, no OCR pipeline on the market helps you, ours included.

Our prompt-injection detection rate on public adversarial corpora is real but partial. We publish our own numbers, including the unflattering ones, and I'd encourage you to distrust anyone who publishes only the flattering ones. The known problem across this whole product category cuts the other way too: over-defense. The InjecGuard work and its NotInject benchmark exist because guardrails that flag every roleplay prompt as hostile are their own kind of broken, and clean-data benchmarks hide the gap — General Analysis measured Azure AI Content Safety at F1 0.193 on adversarial inputs against 0.607 for Bedrock, on tools that look comparable on tidy data.

Layers, not silver bullets. Input gate, output gate, tool scope, blast radius.

EchoLeak is patched. The shape of it isn't going anywhere — an agent reading untrusted content is the product, not the bug. Design for the day it believes something it read.
